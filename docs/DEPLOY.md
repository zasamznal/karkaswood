# Развёртывание и обновление

Три независимые части: **сайт** (статические файлы), **сервер** (каталог и вход владельца) и **домен**. Обновлять можно в любом порядке: новая витрина работает и со старым сервером, и с новым.

## 1. Опубликовать сайт

Сайт раздаётся GitHub Pages из ветки `main`. В `main` попадает только витрина — без `backend/`, `drizzle/`, `docs/`, `tools/`, `package*.json` и `README.md`.

```sh
git fetch origin
git checkout main
git checkout origin/ai-handoff -- index.html 404.html admin assets data embed info .nojekyll
git status            # проверьте список изменённых файлов
git commit -m "Publish the finished storefront"
git push origin main
```

Через одну-две минуты изменения появятся на `https://zasamznal.github.io/karkaswood/`. Проверьте главную, `/info/`, `/admin/` и одну модель на телефоне.

Откатить публикацию: `git revert <хеш коммита>` в ветке `main` и `git push`.

## 2. Обновить сервер до схемы 2

Зачем: прежний сервер хранит только базовые поля. Пока он не обновлён, в панели закрыты замком «Тексты сайта», запасные каналы связи, календарь оформления, комплектация и галереи карточек. Всё остальное работает.

Как узнать версию: откройте `<адрес сервера>/site` в браузере (адрес записан в `assets/config.js`). У обновлённого сервера в конце ответа есть `"schema":2`.

### Собрать

```sh
npm ci
npm run build          # результат: dist/server/index.js
```

### Вариант А. Сервер остаётся на прежней площадке

Замените код работающего сервера файлом `dist/server/index.js` тем же способом, каким он был выложен. База и секреты не меняются: таблицы прежние, новые поля лежат внутри того же документа. После выкладки проверьте `"schema":2` и опубликуйте из панели любую правку.

### Вариант Б. Свой сервер на Cloudflare

Нужен аккаунт Cloudflare (бесплатного тарифа достаточно).

```sh
cp backend/wrangler.example.toml backend/wrangler.toml
npx wrangler login
npx wrangler d1 create karkaswood                       # идентификатор базы впишите в backend/wrangler.toml
npx wrangler d1 execute karkaswood --remote --file=drizzle/0000_workshop.sql --config backend/wrangler.toml
printf '%s' 'ПАРОЛЬ-ВЛАДЕЛЬЦА' | sha256sum               # 64 символа — это KW_OWNER_PASSWORD_HASH
npx wrangler secret put KW_OWNER_PASSWORD_HASH --config backend/wrangler.toml
npx wrangler secret put KW_SESSION_SECRET --config backend/wrangler.toml     # случайная строка от 32 символов
npx wrangler deploy --config backend/wrangler.toml
```

Затем впишите адрес нового сервера (с `/api` на конце) в `PROD_API` файла `assets/config.js` и опубликуйте сайт.

Перенос данных со старого сервера. Новая база пуста, поэтому сервер начнёт со стартового каталога `data/site.json`.

1. До переключения сохраните ответ `<старый адрес>/site` и замените им содержимое `data/site.json` (поля `sha` и `schema` удалите). Так новый сервер стартует с актуальными ценами и названиями.
2. Скрытые карточки в этот ответ не входят. Перед переносом временно включите их показ в панели или перенесите вручную.
3. Фотографии, загруженные через панель, хранятся в базе старого сервера и адресуются как `<старый адрес>/media/…`. Сохраните их файлами и загрузите в карточки заново после переключения.

### Проверка на своём компьютере

```sh
npm run dev:api        # сервер на http://127.0.0.1:8787, пароль владельца: demo
npm run test:api       # в соседнем окне: все строки должны начинаться с PASS
```

Сменить пароль владельца: задайте новый `KW_OWNER_PASSWORD_HASH`. Все действующие сеансы при этом завершатся.

## 3. Свой домен

1. Подключите домен к GitHub Pages (Settings → Pages → Custom domain) или перенесите файлы на другой хостинг.
2. Впишите новый адрес сайта в `SITE_URL` в двух местах: `assets/config.js` и `backend/worker.mjs`. Сервер принимает запросы панели только с этого адреса.
3. Пересоберите и выложите сервер, опубликуйте сайт.
4. В `index.html` обновите `og:url`, `og:image` и `<link rel="canonical">`, в `404.html` — пути `/karkaswood/`.

## 4. Открыть сайт для поисковых систем

Сейчас сайт закрыт от индексации: заказчик ещё не утвердил его. Когда будет готово:

1. Удалите строку `<meta name="robots" content="noindex,nofollow">` из `index.html` и `info/index.html`. В `admin/index.html`, `embed/index.html` и `404.html` оставьте.
2. Добавьте сайт в Яндекс Вебмастер и Google Search Console.
3. На своём домене положите в корень `robots.txt` и `sitemap.xml` с двумя адресами: главная и `/info/`.

До открытия индексации убедитесь, что заполнены реквизиты продавца и адрес для обращений.

## 5. Резервная копия

Каталог целиком отдаёт `<адрес сервера>/site` — сохраните ответ в файл. Скрытые карточки туда не попадают: их видно только в панели после входа.
